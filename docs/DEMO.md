# Демонстрация BizPilot AI (3–5 минут)

Сценарий для работодателя или клиента: показать путь «заявка → AI-анализ →
подтверждение → CRM-действие → необязательная автоматизация». Это не список
страниц, а короткая история о том, как команда перестаёт терять контекст
обращений.

## Подготовка (только на выделенной демо-БД)

1. Используйте **отдельную** базу с синтетическим seed. Не запускайте сценарий
   на БД, где могут быть реальные контакты или заявки.
2. Примените миграции и seed, затем запустите приложение:

   ```bash
   pnpm prisma:generate
   pnpm prisma:migrate
   pnpm prisma:seed
   pnpm dev
   ```

3. Войдите как `admin@demo.local`; пароль — значение `SEED_ADMIN_PASSWORD` из
   вашего `.env` (в Git и README его нет).
4. AI: для честной демонстрации нужен реальный provider
   (`AI_PROVIDER=openai-compatible`, `ALLOW_MOCK_AI=false`). Если credentials
   нет, допустим `AI_PROVIDER=mock` + `ALLOW_MOCK_AI=true`; обязательно скажите
   аудитории, что ответ mock.
5. n8n/Telegram можно не запускать: CRM работает без них, события остаются
   `PENDING`. Для показа реальной доставки нужны credentials (см. `docs/N8N.md`);
   в текущей ревизии это не проверялось.

## Сценарий

### 0:00–0:30 — Вход и Dashboard [N]

- Войдите под ADMIN.
- Покажите баннер **Demo data**: заявки и задачи с префиксом `[DEMO]` вымышлены.
- На Dashboard покажите KPI из PostgreSQL: всего заявок, контакты, задачи,
  Conversion Rate, воронку по статусам и 14-дневную динамику. Данные не
  захардкожены; отдельной страницы Analytics нет — аналитика находится здесь.

### 0:30–1:30 — Новая заявка [N]

- «Заявки» → «Новая заявка».
- Название: `Демо: автоматизация отчётности`.
- Текст (контакты есть в тексте, чтобы показать извлечение):

  > Нужен еженедельный отчёт по продажам с отправкой в Telegram. Бюджет
  > 300 000 руб., срок — две недели. Контакт: Иван Петров,
  > ivan.petrov@example.com, +7 900 111-22-33.

- Сохраните. Заявка появляется в списке; поиск, фильтры и пагинация работают
  на сервере.

### 1:30–2:30 — AI-анализ [N]

- Откройте заявку → «AI-анализ» (или раздел «AI-помощник»).
- Нажмите «Анализировать». Покажите summary, категорию, intent, приоритет и
  Lead Score, score breakdown, факторы, риски, недостающую информацию,
  контакты, извлечённые только из текста, и черновик ответа.
- Подчеркните: AI не меняет заявку и не отправляет сообщения автоматически.
  Черновик можно скопировать, но отправка — только вручную.
- Исторически этот поток проверен с реальным provider и mock-E2E; в текущей
  ревизии запрос не выполнялся.

### 2:30–3:30 — Подтверждение и CRM [N]

- Нажмите «Применить к заявке». Только теперь summary, score, категория,
  намерение и приоритет сохраняются.
- Вернитесь в карточку заявки: поля обновились, история анализов доступна.
- Создайте контакт (или свяжите существующий) и задачу «Позвонить клиенту»,
  назначьте ответственного. Покажите связи заявка ↔ контакт ↔ задача.

### 3:30–5:00 — Автоматизация и роли [N / runtime BLOCKED]

- «Настройки» → блок автоматизации: статус n8n/Telegram, журнал событий,
  попытки и ошибки.
- Если n8n выключен: событие в `PENDING`, CRM продолжает работать. Это
  осознанное свойство: n8n необязателен.
- Кнопка ручного retry для `FAILED` доступна ADMIN/MANAGER; объясните
  идемпотентность: повтор не создаёт дубль. Это проверено unit/integration-тестами
  исторически, но не в текущей ревизии.
- Войдите как OPERATOR: раздел автоматизации недоступен, удаление запрещено
  сервером (не только скрыто в UI).

## Что сказать в завершение

- PostgreSQL — источник истины; AI не имеет доступа к БД.
- Все ответы модели валидируются Zod; контакты проверяются по исходному тексту.
- n8n/Telegram — необязательный слой; сбой интеграции не ломает CRM.
- Секреты живут только в ENV/credentials; в Git и UI их нет.
- Архитектура разделена на presentation, services и infrastructure; бизнес-логика
  не находится в Route Handlers или UI.

## Ограничения, которые нужно назвать честно

- Скриншоты сняты на отдельной seeded БД (40 изображений, каталог
  `artifacts/visual-review/phase1/`, не коммитится); визуальный checklist не
  подписан, поэтому визуальный PASS не заявляется.
- Integration и E2E выполнены 2026-11-23 на изолированном кластере PostgreSQL 16
  (49/49 и 12/12); первый integration-прогон дал транзиентный сбой, который не
  воспроизвёлся. MANAGER allow/deny не покрыт E2E.
- Локальный Docker Compose не проверялся (Docker отсутствует); проверка вынесена
  в CI job `docker`.
- Реальный n8n + Telegram E2E не выполнен без credentials; workflow —
  draft для импорта.
- Rate limit in-memory, JWT без отзыва сессий, multi-tenancy ограничена одной
  Workspace в seed.
